# Лабораторная №3 — обнаружение СИЗ на YOLOv8

Исходный проект сохранён в README.md. Работа ведётся в ветке lab/03-ppe; полный список требований и статусов — reports/compliance.md. Набор и группировка — data/README.md. Итоговые метрики появятся в reports/lab03-report.md после завершения опытов.

## Оборудование и окружение

Windows, Intel Core Ultra 5 125H (14 ядер / 18 потоков), 16 GB RAM, Intel Arc Graphics; вычисления PyTorch на CPU, 6 потоков, workers=0, batch=4. Python 3.13; точные версии зависимостей в requirements-lock.txt. Интернет нужен для зависимостей и архива, обучение полностью локальное.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\.venv\Scripts\python.exe scripts/download_data.py
.\.venv\Scripts\python.exe scripts/prepare_data.py
.\.venv\Scripts\python.exe -m ppe.cli validate-data
.\.venv\Scripts\python.exe -m pytest -q
```

Манифест восстанавливает фиксированные 135/31/28 изображений и проверяет SHA256. Если зеркало обновилось и архив не совпадает с provenance.json, остановиться и получить исходную версию, не пересоздавать манифест ради прохождения проверки.

## Эксперименты

```powershell
.\.venv\Scripts\python.exe -m ppe.cli upstream
.\.venv\Scripts\python.exe -m ppe.cli e0
.\.venv\Scripts\python.exe -m ppe.cli train --config configs/e1.yaml
.\.venv\Scripts\python.exe scripts/finish_experiments.py
```

Последняя команда обучает E2, оценивает обе модели на validation, записывает выбор в reports/selection.json, затем оценивает test и создаёт галереи и системные измерения выбранной модели. Повторно использовать занятые каталоги запусков нельзя: для нового опыта задать новые name. Пробная эпоха — configs/probe.yaml, её веса не используются в E1/E2.

Версия Ultralytics добавляет task-каталог к относительному project: фактические обучающие запуски находятся в runs/detect/runs/ppe/. Точный каталог печатается при завершении и содержит provenance.json, args.yaml, results.csv и weights/best.pt. Веса и полные временные запуски не добавляются в Git; метрики, контрольные суммы и графики сохраняются в отчёте. Исходные models/best.pt и models/yolov8n.pt унаследованы от upstream, первая модель не используется для сравнения E1/E2.

## Проверка результата и участие автора

Автоматические тесты: схема/диапазоны разметки, пересечение групп/имён/хэшей, целостность фиксированного набора, координаты, размер визуализации, дублирующиеся детекты и контрольная схема вывода модели. Статическая проверка: `ruff check src scripts tests`.

Агент визуально просмотрел 40 кадров и записал замечания в reports/annotation-audit.md. Студент должен самостоятельно подтвердить ручной аудит и объяснить код на защите; независимое человеческое рецензирование и устная защита не подменяются проверками агента. Контрольные вопросы и быстрые команды — reports/defense.md. Правила отказа и отката — reports/system-policy.md.

## Использование ИИ

Инструмент: Codex. Запрос: выполнить локально лабораторную согласно двум предоставленным PDF, создать форк исходного проекта и проверять соответствие требованиям. ИИ использован для реализации подготовки данных, тестов, экспериментов, диагностик и черновиков документации. Приняты: групповое разбиение, хэширование, проверки схемы и конфигурации. Изменены: исходные пути Kaggle, исключены готовые offline-аугментации, снижены epochs/batch до фиксированных ресурсных значений. Отклонено использование upstream best.pt в качестве начальных весов E1/E2 из-за обучения на том же датасете.

Проверка: pytest, Ruff, реальные локальные E0/E1/E2, фиксированные журналы, визуальный аудит и сверка артефактов. Риски: спорные исходные аннотации и атрибуция составных изображений, малые тестовые классы, ошибки программных интерфейсов и метрик, остаточная утечка неизвестных сцен. Секреты GitHub в код/логи не включаются. Результаты агента требуют понимания автором; метрики не генерируются из предположений.
