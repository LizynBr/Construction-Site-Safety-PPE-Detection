# Дополнительный опыт после E1/E2

Запрошен пользователем после просмотра первого отчёта. Исходные E1/E2 и test-результаты сохраняются.

Наблюдение: у E2 train loss снижается до 20-й эпохи, validation mAP50-95 к концу растёт. Недообучение — проверяемая гипотеза, а не установленная единственная причина. Набор train=135 мал и неоднороден; validation имеет очень мало объектов ряда PPE-классов, поэтому эффект может быть нестабилен.

E3 отличается от E2 только epochs=50 вместо 20 (и техническим именем запуска). Инициализация снова исходными COCO-весами, freeze=10, seed=42, остальные настройки прежние. Обучение только локально на CPU. Выбор лучшего checkpoint по validation. Test уже просмотрен в первой работе, поэтому он не является полностью слепым holdout для дальнейших решений; для подтверждения обобщения потребуется новая независимая тестовая выборка. В этом дополнительном опыте test повторно не оценивается.

Критерий улучшения заранее: validation mAP50-95 >0.120886; дополнительно сравнить AP/recall PPE-классов и признаки переобучения. Увеличение числа эпох может не улучшить результат; это будет отражено без замены исходных чисел.

Команда: `python -m ppe.cli train --config configs/e3.yaml`, затем `python -m ppe.cli evaluate --weights runs/detect/runs/ppe/e3-freeze10-50epochs/weights/best.pt --split val --name e3-val`.
